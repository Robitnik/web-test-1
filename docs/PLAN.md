# Ресерч і план (2026-11-11)

## 1. Як сайти виявляють автоматизацію (5 шарів)

| Шар | Що перевіряють | Чим закривається |
|---|---|---|
| 1. Сліди драйвера | `navigator.webdriver`, витік `Runtime.enable` по CDP, глобалі `__playwright*`/`cdc_*`, прапорець `--enable-automation` | patchright (патчі в драйвері) |
| 2. Узгодженість відбитка | UA ↔ Client Hints, `HeadlessChrome`, WebGL SwiftShader, порожні plugins, Notification ↔ permissions, екран ↔ вікно | справжній Chrome, видимий режим, без підміни UA |
| 3. Мережа | TLS (JA3/JA4) і HTTP/2 відбиток, репутація IP (датацентр) | справжній Chrome дає справжній TLS; IP: резидентні/власні проксі |
| 4. Поведінка | рух миші, рівні інтервали кліків, швидкість набору, маршрут по сайту | шар «людських» дій (Ф4) |
| 5. Челенджі | Cloudflare Turnstile/interstitial, reCAPTCHA v3 score | теплий профіль з історією + все вище; гарантії немає |

## 2. Інструменти (стан на 2026)

| Інструмент | Як працює | Плюс | Мінус |
|---|---|---|---|
| **patchright** ✅ обрано | патчений драйвер Playwright (Chromium/Chrome) | API Playwright 1:1, закриває витік `Runtime.enable`, без `--enable-automation`, ізольований світ | лише Chromium; Console API вимкнений; на Cloudflare буває interstitial |
| playwright-stealth | JS-скрипти перед завантаженням сторінки | просто | автор сам називає proof-of-concept; витік CDP лишається; самі патчі детектуються |
| rebrowser-patches | патч витоку `Runtime.enable` | точковий | у бенчмарках на рівні звичайного Playwright |
| nodriver | CDP напряму, без webdriver (наступник undetected-chromedriver) | у травневому тесті 2026 на 31 Cloudflare-цілі: 0 жорстких блоків | не API Playwright, інша модель коду |
| Camoufox | форк Firefox з підміною відбитка на рівні C++ | найкращий для ротації відбитків | лише Firefox, переписувати скрипти |

**Чому patchright + справжній Chrome:** той самий API, що й Playwright (і що вже працює в
AISeoTools), найменше коду, справжній TLS і справжній набір кодеків. Якщо ціль сидить за
агресивним Cloudflare і patchright впирається в interstitial, наступний кандидат — nodriver
як окремий бекенд за тим самим інтерфейсом `Browser` (Ф5).

Числа з бенчмарків — орієнтир: частина джерел вендорські, і детекція — гонка, а не стан.

## 3. Відомі пастки patchright

- `page.evaluate` за замовчуванням в **ізольованому світі** → глобалі сайту не видно.
  Рішення: `eval_main()` (`isolated_context=False`). Тест `test_live.py` це фіксує.
- Console API вимкнений → події `page.on("console")` не приходять (це плата за stealth).
- Кастомні `user_agent` / `extra_http_headers` **ламають** stealth: не ставити.
- Headless детектується легше; на сервері — Xvfb, а не `headless=True`.
- Один профіль = один процес Chrome. Два процеси на одній теці ламають cookies → `profile.py`.
- Chrome без sudo (`~/.local/opt`) **не оновлюється сам** → перезапускати `install_chrome.sh`.

## 4. План

### Ф0 — фундамент ✅ (зроблено)
Репо, `uv`-оточення, patchright, Chrome без sudo, `Browser`/`BrowserConfig`, захист профілю,
діагностика відбитка, CLI `doctor/open/check`, юніт-тести + живий тест.

### Ф1 — шар дій
- `actions.py`: `click`, `fill`, `select`, `wait_for` з таймаутами і зрозумілими помилками.
- Ретраї навігації (мережеві помилки, 429/503 = наш темп, бекоф, не «зламана сторінка»).
- Трасування на падінні (`context.tracing` → `out/trace-*.zip`), логування в файл.
- Синхронна обгортка для скриптів без `asyncio`.

### Ф2 — базова лінія детекції
- `webtest check --sites sannysoft creepjs browserscan` у видимому і headless режимі.
- Зберегти відбитки як еталон, тест-регресія: нова версія patchright/Chrome не додає red flags.

### Ф3 — мережа
- Перевірка проксі (IP, гео), автопідбір `locale`/`timezone` під гео проксі (розбіжність = сигнал).
- Пул проксі, прив'язка проксі до профілю (профіль не міняє IP між сесіями).

### Ф4 — поведінка
- Рух миші кривими, скрол порціями, набір із затримками, джитер між діями (`human_pause` уже є).

### Ф5 — сесії й профілі
- Кілька профілів, пул, «прогрів» профілю (історія, cookies).
- Режим **attach**: `connect_over_cdp` до вже запущеного Chrome (тепла сесія з логінами,
  як `browser-up` у AISeoTools).
- Запасний бекенд nodriver за тим самим інтерфейсом, якщо Ф2 покаже стіну Cloudflare.

### Ф6 — сервер
- Docker-образ з Chrome + Xvfb, не від root, профіль на томі.

### Ф7 — CI
- GitHub Actions: ruff + юніт-тести (живі тести в CI не запускаються).

## 5. Відкриті питання до власника
